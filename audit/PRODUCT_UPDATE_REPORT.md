3. **Identifier detection.** Any input containing @ is validated as email, trimmed and lowercased with Locale.ROOT. Other input is passed to existing registrationPhone. Invalid input is rejected before Auth. Signup and login use the same detector.

The broader international contact branches remain unchanged, but registrationPhone rejects non-Kenyan results. 0715501556, +254715501556, 254715501556, 715501556 all yield +254715501556. The equivalent 01 formats also work.

5. **Current phone/password configuration.** Read-only GET /auth/v1/settings confirmed external.email=true, external.phone=true, mailer_autoconfirm=true, phone_autoconfirm=true, disable_signup=false. Those settings support password signup without phone confirmation. The installed 2.6.1 source was inspected: Phone.Config has phone/password and grantType=password. Mock HTTP tests verify repository requests. No live account was created: hosted Auth provisioning, carrier delivery and device UX are not end-to-end tested. If confirmation is enabled later, the app reports that limitation and does not add an OTP flow or synthetic signup workaround.

6. **Profile completion.** Reuses the existing Complete profile dialog and saveProfile RPC. Email signup retains authenticated email and asks for missing phone; phone signup retains authenticated phone and asks for missing email. Both known contacts are hidden. Missing name/username are requested; reserved placeholders are treated as missing. A complete profile can still edit name/username. Submission merges hidden known values and uses complete_member_profile(p_full_name,p_username,p_email,p_phone). Auth contacts hydrate only the matching owner's row, and saved nonempty profile contacts take precedence. Existing full signup metadata can still complete through the old hydration path.

7. **Existing-account compatibility.** Email accounts use Email/password. Native phone accounts use Phone/password. If native phone login returns invalid credentials, a login-only fallback tries the existing +254-normalized-number-without-plus @auth.kashke.local identity. No fallback on network/provider/confirmation failures; no synthetic signup. Existing Auth UUIDs, sessions and profile relationships are retained. No identity migration, merge, deletion or recreation occurs. Other synthetic domains are not found in the current implementation and are not invented as new compatibility schemes. Where a native and legacy account both exist for the same number, successful native credentials take precedence; identities are never merged. Profile contact email does not create an alternative Auth login identity.

10. **Discovered support policy.** The inspected hosted record_trust_event ignores the caller's nominal points for configured events: COMMUNITY_SUPPORT awards +2. Reconciled acceptance invokes it only after funding. It deduplicates by user, event type and related loan.

11. **Discovered repayment policy.** LOAN_COMPLETED awards +2 if completed by original deadline, +1 by extended deadline, otherwise 0. Both finalize_repaid_loan and repayment RPC may observe completion; record_trust_event already prevents a second same-loan event. Interest-first allocation and operation receipts are retained.

12. **First support implementation.** Inside existing record_trust_event, the first genuine funded lender event records 200 instead of 2. Eligibility requires no previous COMMUNITY_SUPPORT history and no other funded loan for that lender. Later events remain +2. Sending, declining, cancelling, expiring or failing acceptance cannot reward it.

13. **First full repayment implementation.** The first genuine REPAID loan with amount_paid=total_repayment and completed_at set records 400 instead of the normal 2/1/0. Eligibility requires no previous LOAN_COMPLETED history and no other completed fully-paid loan for that borrower. Partial payments do not call completion. Later completions retain timing-based 2/1/0. First completion qualifies regardless of lateness; existing penalties still apply separately, so net score changes can differ from the positive reward event.
